HTTP API

With one database the unprefixed routes are the whole API. With several, unprefixed routes follow the first name in DBADMINER_DATABASES. The same paths exist under /api/databases/{name}/….

Read routes

  • GET /api/databases
  • GET /api/databases/{name}/info
  • GET /api/databases/{name}/tables
  • GET /api/databases/{name}/tables/{schema}/{table}
  • GET /api/databases/{name}/tables/{schema}/{table}/schema (columns, indexes, foreign keys, DDL)
  • GET /api/databases/{name}/tables/{schema}/{table}/rows?limit&offset&order&dir&count=1
  • POST /api/databases/{name}/query with {"sql":"select 1"} and Content-Type: application/json
  • GET /api/info
  • GET /api/tables
  • GET /api/tables/{schema}/{table}
  • GET /api/tables/{schema}/{table}/schema
  • GET /api/tables/{schema}/{table}/rows?…
  • POST /api/query

count=1 opts into COUNT(*). The page size is capped by MaxRows.

Write routes

Write routes require full access (DBADMINER_ACCESS=full). They return 403 while read-only.

  • POST /api/tables create table
  • POST /api/views create view
  • PATCH /api/tables/{schema}/{table} alter columns
  • DELETE /api/tables/{schema}/{table}?type=table|view
  • POST|DELETE …/indexes[…]
  • POST|DELETE …/foreign-keys[…]
  • POST|PATCH|DELETE …/rows insert / update / delete by primary key

GET /api/databases lists name, dialect, schema, access, and readOnly. It does not include the host, user, or password. Row edit APIs require a primary key; tables without one stay SQL-console only.
